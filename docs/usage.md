# 보안관제 포털 사용 안내 (1쪽)

## 처음 로그인
1. 관리자가 알려 준 아이디·비밀번호로 로그인합니다.
2. 처음에는 QR 코드가 나옵니다. 구글 OTP 앱으로 스캔한 뒤 6자리 코드를 입력합니다.
3. 이후에는 로그인할 때마다 OTP 6자리를 입력합니다. 비밀번호를 5번 틀리면 계정이 잠기며, 관리자가 풀어 줍니다.
4. 관리자가 아닌 계정은 관리자가 등록한 IP에서만 로그인할 수 있습니다.

## 화면
| 메뉴 | 하는 일 |
|---|---|
| 대시보드 | 수집이 정상인지, 최근 24시간 새로 들어온 위협정보, 수집 상태, 최근 알림 |
| 위협정보 | 종류·기관·기간·키워드로 검색, 값을 누르면 제공 기관 목록과 이력 |
| 보고서 | 조건을 고르면 PDF로 내려받기 (최대 5,000건) |
| 자산 | 점검 대상 자산 목록. 자산을 누르면 점검 결과·이력·날짜 비교 |
| (관리자) 사용자 | 계정 만들기, 허용 IP, 잠금 해제, OTP 초기화 |
| (관리자) 수집 출처 | 위협정보를 가져올 기관·주소 등록 |
| (관리자) 화이트리스트 | 제외할 IP·도메인 등록. 목록에는 남고 SIEM 연동에서만 빠집니다 |
| (관리자) SIEM 연동 | API 키 발급·폐기 |
| (관리자) 감사 로그 | 누가 언제 무엇을 했는지 |

## 매일 돌아가는 일 (자동)
- 매시 17분: 위협정보 수집 (GitHub Actions “위협정보 수집”)
- 매일 02:30: 자산 점검 (“자산 점검”) — 점검 허가를 확인하고 등록한 자산만
- 매일 03:10: 정리 — 90일 지난 위협정보 비활성, 1년 지난 점검 결과·알림 삭제

## 자산 점검 시작하기
1. 자산 메뉴에서 자산을 등록합니다. “점검 허가 확인”을 체크해야 등록됩니다. 사설 IP는 등록할 수 없습니다.
2. 처음에는 3~5개만 등록하고 GitHub Actions → “자산 점검” → Run workflow에서 점검 수 제한에 3을 넣어 실행합니다.
3. 자산 상세에서 열린 포트·서비스·인증서 만료일을 확인하고, 이상이 없으면 자산을 늘립니다.
4. 점검은 GitHub 서버 IP에서 나갑니다. 대상 방화벽·IPS가 차단하면 “실패”나 “일부만 점검”으로 기록되니 GitHub Actions IP 대역을 허용해야 합니다.

## 알림
화면 위 종 아이콘의 숫자가 읽지 않은 알림입니다(1분마다 갱신). 새 포트 열림·닫힘, 새 노출 페이지, 인증서 만료 30일 전, 접속 불가를 알려 줍니다.

## 문제가 생기면
- 대시보드 맨 위 띠가 빨간색이면 수집 출처 중 실패·지연이 있다는 뜻입니다. 수집 상태 표에서 원인을 확인합니다.
- 로그인이 안 되면 관리자에게 잠금·허용 IP·OTP 초기화를 요청합니다.

## VirusTotal 평판 기록 (위협정보 상세 화면)
1. 위협정보 목록에서 값을 눌러 상세 화면을 엽니다 (IP·도메인·파일 해시만 해당).
2. "VirusTotal에서 분석 보기"를 눌러 새 창에서 결과를 확인합니다.
3. 아래 "평판 기록하기"에서 판정(악성·의심·정상·미확인)과 메모를 남기면 이력으로 쌓이고, 목록의 "평판" 열에 최근 판정이 표시됩니다.
4. (선택, 관리자) Vercel 환경변수 `VT_API_KEY`에 VirusTotal 무료 API 키를 넣으면 "API로 자동 조회·기록" 버튼이 켜집니다. 무료 키는 분당 4건·하루 500건 한도이며, 화이트리스트·자산과 일치하는 값은 외부로 보내지 않습니다.

## 수동 점검 설정 (자산 점검 화면의 "선택한 자산 지금 점검" 버튼)
점검은 GitHub 서버에서 실행되므로, 포털이 GitHub에 실행 신호를 보낼 수 있도록 토큰을 한 번 등록해야 합니다. 토큰은 채팅·문서에 적지 말고 Vercel에만 직접 입력하세요.
1. GitHub 오른쪽 위 프로필 → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
2. Repository access: "Only select repositories"에서 `secops-portal`만 선택. Permissions → Repository permissions → **Actions: Read and write** (다른 권한은 모두 "No access"). 만료일은 90일 등으로 정합니다.
3. 만들어진 토큰 값을 복사해 Vercel → secops-portal → Settings → Environment Variables에 이름 `GITHUB_DISPATCH_TOKEN`으로 추가(Production 선택)하고 다시 배포(Redeploy)합니다.
4. 자산 점검 화면에서 자산을 체크하고 버튼을 누르면 2~10분 뒤 각 자산 화면에 결과가 나타납니다. 만료일이 되면 같은 방법으로 토큰을 새로 만들어 교체하세요.

## VirusTotal 자동 조회 (사람이 누르지 않아도 평판을 가져오기)
- GitHub Actions "VirusTotal 자동 조회"가 3시간마다 최대 50건, 하루 최대 400건을 조회해 평판을 기록합니다 (무료 키 한도 분당 4건·하루 500건 보호).
- 대상: 활성 · SIEM 제외가 아닌 · IP/해시/도메인 · 아직 평판 기록이 없는 값 (IP → 해시 → 도메인 순, 최근 확인된 것부터). 화이트리스트·자산과 일치하는 값은 보내지 않습니다.
- 켜는 법: 저장소 Settings → Secrets and variables → Actions → New repository secret에 이름 `VT_API_KEY`, 값에 VirusTotal API 키를 **직접** 입력합니다. (상세 화면의 수동 "API로 자동 조회" 버튼을 쓰려면 Vercel에도 같은 이름으로 넣어야 합니다.)
- 결과는 상세 화면의 "평판 기록 이력"(출처: VirusTotal API, 메모 "자동 조회")과 목록의 "평판" 열에 나타납니다.
- 주의: VirusTotal 무료 API는 상업적 사용이 제한됩니다. 조직의 정식 업무에 쓰기 전에 VirusTotal 이용 약관을 확인하세요.

## IP 주소·국가(국기+코드) 열 (위협정보 목록)
- 도메인은 DNS로 찾은 IP를, IP는 자기 자신을 보여 주고, IP 대역의 국가를 whois의 후속 표준(RDAP)으로 조회해 국가 코드와 국기로 표시합니다. URL·해시·메일은 "-"입니다.
- GitHub Actions "IP·국가 확인"이 1시간마다 도메인 최대 5,000개의 IP를 찾고(구글 8.8.8.8 → 8.8.4.4 → 클라우드플레어 1.1.1.1 → KT 168.126.63.1·.2 → SK브로드밴드 → LG U+ → 서버 기본 DNS 순으로 물어 처음 답하는 공인 IP 사용), 국가는 5개 지역 인터넷 등록기관(APNIC·RIPE·ARIN·LACNIC·AFRINIC)이 공개하는 "IP 대역별 국가 목록"으로 채웁니다(14일마다 갱신, IP별 조회 한도 없음). 목록에 없는 드문 IP만 RDAP으로 추가 조회합니다. 처음 쌓인 수만 건은 며칠에 걸쳐 채워지며, 그동안 "확인 대기"로 보입니다.
- DNS에서 찾지 못한 도메인(이미 사라진 도메인 등)은 "DNS에 없음"으로 표시하고 7일 뒤 다시 확인합니다. 찾은 IP는 30일마다 다시 확인합니다.
- 도메인의 DNS 조회만 하며, 대상 사이트에는 접속하지 않습니다. 국가는 IP 대역의 "등록 국가"이므로 실제 서버 위치와 다를 수 있습니다(CDN·해외 호스팅 등).

### 도메인 IP 찾는 순서 (DNS)
- 구글(8.8.8.8, 8.8.4.4) → 클라우드플레어(1.1.1.1) → KT(168.126.63.1, 168.126.63.2) → SK브로드밴드(210.220.163.82) → LG U+(164.124.101.2) → 마지막으로 서버의 기본 DNS 순서로 묻고, 처음 공인 IP를 알려주는 곳의 답을 씁니다. 시간 초과·오류가 나면 다음 서버로 넘어갑니다.
- 마지막 기본 DNS 조회는 ping이 주소를 찾는 방식과 같습니다. ping은 결국 DNS로 IP를 묻는 것이라 별도로 ping을 쓰지 않아도 같은 결과입니다.
- 악성 사이트를 막는 보안 DNS(Quad9, OpenDNS 등)는 막힌 도메인에 IP 없이 "없음"으로 답하므로 일부러 쓰지 않았습니다. 0.0.0.0·127.x 같은 사설·차단 응답은 건너뛰고 다음 서버에 묻습니다.
- 한 도메인이 모든 서버에서 "없음"이면 "DNS에 없음"으로 표시하고 7일 뒤 다시 확인합니다. 조회 방식을 바꾸기 전에 "DNS에 없음"으로 기록된 도메인은 다음 실행에서 한 번 더 확인합니다.
- 주의: KT 등 국내 통신사 DNS는 유해 사이트 차단 안내 페이지의 IP를 대신 알려 줄 수 있습니다. 구글 등을 먼저 묻는 이유입니다.

## 환경점검 메뉴 (포트·DNS·WHOIS·Reverse IP·내 IP)

왼쪽 메뉴 "환경점검"에서 위쪽 탭으로 도구를 고릅니다. 로그인한 모든 사용자가 쓸 수 있습니다.

- **내 공인 IP**: 지금 접속한 주소, 역방향 이름, 국가. VPN·프록시를 쓰면 그 서버 주소가 나옵니다.
- **포트 체커**: 도메인/IP와 포트(예: `80, 443, 8000-8005`, 최대 20개)를 넣고, "점검 권한이 있는 대상" 체크 후 조회. 열림 / 닫힘 / 응답 없음(방화벽)으로 보여 줍니다. 연결만 하고 데이터는 보내지 않습니다.
- **DNS 조회**: A·AAAA·CNAME·MX·NS·TXT·SOA를 선택한 DNS 서버(구글·클라우드플레어·KT·서버 기본)로 조회. IP를 넣으면 PTR 조회.
- **WHOIS 조회**: 표준 WHOIS(43번 포트)로 IANA → 담당 기관 순서로 따라가 결과를 보여 줍니다.
- **Reverse IP**: 같은 IP를 쓰는 도메인. 이 포털이 수집한 도메인 + 외부 공개 DB(HackerTarget, 하루 무료 한도가 있어 초과 시 안내만 표시).

안전장치: 모든 사용은 감사 로그(`tool_use`)에 남고, 1분에 20회까지이며, 내부망·예약 주소(127.0.0.1, 10.x, 192.168.x 등)는 점검하지 않습니다. 이 서버(Vercel)에서 나가는 요청이라 "우리 방화벽에서 본 모습"이 아니라 "인터넷에서 본 모습"입니다.

## 사용자 계정 수정 · OTP 사용 여부

- 사용자 관리 > "새 사용자"에서 **OTP 인증: 사용(권장) / 사용 안 함**을 고를 수 있습니다. "사용 안 함"은 아이디·비밀번호와 허용 IP만으로 로그인합니다.
- 목록의 **수정** 버튼 → 이름, 권한, OTP 사용 여부, 새 비밀번호(비우면 유지)를 바꿀 수 있습니다. 비밀번호를 바꾸면 로그인 실패 횟수도 0이 됩니다. 본인 권한은 바꿀 수 없습니다.
- OTP를 다시 "사용"으로 바꾸면, 등록이 안 된 계정은 다음 로그인 때 QR을 등록합니다.
- 반영하려면 설정(setup) 작업의 **db-update**를 한 번 실행하세요 (새 열 추가).

## 계정 삭제

사용자 관리 목록 왼쪽 체크박스로 계정을 고르고(맨 위 체크박스는 전체 선택) **선택한 계정 삭제**를 누릅니다. 확인창 후 삭제되며 되돌릴 수 없습니다. 본인 계정은 선택할 수 없고, 관리자가 한 명도 남지 않게 되는 삭제는 거부됩니다. 삭제한 계정의 감사 로그는 남습니다(사용자 칸만 비워짐). 계정을 지우지 않고 막고 싶다면 비밀번호 변경이나 허용 IP 삭제를 쓰세요.

## 국가코드로 위협정보 조회

위협정보 > 검색 조건의 **국가코드**에 두 글자(예: KR, US, CN)를 넣고 검색합니다. IP는 그 IP의 국가, 도메인은 DNS로 찾은 IP의 국가 기준입니다. 국가가 아직 채워지지 않은 항목(enrich 작업 전)은 나오지 않습니다. 새 인덱스가 있으므로 설정(setup) 작업의 db-update를 한 번 실행하세요.

## 보안뉴스

- 왼쪽 메뉴 **보안뉴스**(보고서 위). 목록은 연번·등록일시(한국시간)·제목·언론사이며, 제목을 누르면 본문 일부와 **원문 보기** 링크가 있는 상세 화면이 열립니다. 쪽 이동·번호 입력·10/50/100개 보기는 위협정보와 같습니다. 수집 검색어별 필터와 제목·언론사·본문 검색이 있습니다.
- 수집: GitHub Actions **보안뉴스 수집**이 매일 06:40(KST)에 해킹, 사이버해킹, 사이버보안, 정보유출, 정보보안으로 구글 뉴스를 검색합니다(키 필요 없음). 같은 기사는 한 번만 저장됩니다. 처음 한 번은 수동 실행(Run workflow)에서 days를 7 정도로 넣으면 지난 일주일치가 채워집니다.
- 네이버도 함께 쓰려면: 네이버 개발자센터(developers.naver.com)에서 애플리케이션을 등록하고 "검색" API를 선택해 Client ID/Secret을 받은 뒤, GitHub Secrets에 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`을 직접 등록하세요(채팅에 올리지 마세요). 없으면 구글만 수집합니다.
- 기사를 누르면 수집한 **본문(최대 3만자)**과 **출처(언론사·등록일시·원문 링크)**가 함께 보입니다. 사내 열람용이며 외부 공유는 하지 마세요(저작권은 각 언론사). 유료·로그인 기사, 구글 링크 일부는 본문을 못 가져와 비어 있을 수 있고 이때는 원문 링크를 쓰세요. 본문이 짧게 저장된 최근 7일 기사는 다음 수집 때 다시 시도합니다. 네이버 키를 등록하면 원문 주소가 바로 나와 본문 확보율이 훨씬 높습니다.
- 반영하려면 setup 작업의 **db-update**를 한 번 실행하세요(새 표 추가).

## 대시보드 자동 갱신

대시보드는 화면을 켜 둔 상태에서 10분마다 데이터를 다시 불러옵니다(위쪽 "기준" 시각이 바뀝니다). 다른 탭을 보고 있던 동안 10분이 지났다면 대시보드 탭으로 돌아올 때 바로 갱신합니다. 페이지 전체를 다시 여는 것이 아니라 데이터만 갱신하므로 깜빡이지 않습니다.

## 자산 위험등급 (안전·주의·위험)

자산점검 목록의 자산명 오른쪽 **위험등급**은 각 자산의 **가장 최근 점검 결과**로 정합니다. 마우스를 올리면 근거가 보입니다.

| 등급 | 표시 | 기준 |
|---|---|---|
| 위험 | 적색 원 | 외부에 열린 위험 포트(Telnet·FTP·RDP·SMB·VNC, DB: MySQL·MS SQL·Oracle·PostgreSQL·Redis·MongoDB·Elasticsearch·Memcached 등), 설정·소스·백업·서버정보 파일이 열람(200)됨, 인증서 만료 |
| 주의 | 황색 원 | SSH·SMTP·SNMP·LDAP 등 확인이 필요한 포트 열림, 관리자·로그인 페이지 접근 가능, 인증서 30일 이내 만료, 최근 점검에 응답 없음 |
| 안전 | 녹색 원 | 위 항목이 발견되지 않음 |
| 미점검 | 회색 원 | 아직 점검 결과가 없음 (등급을 매기지 않음) |

"안전"은 점검한 범위에서 위험 징후가 없다는 뜻이며 취약점이 없다는 보증은 아닙니다. 기준 목록은 `lib/risk.ts`에서 바꿀 수 있습니다.

## 정시 실행 (Supabase 예약)

GitHub의 예약 실행(cron)은 늦거나 통째로 빠질 수 있어서, 정시 실행은 Supabase가 맡습니다. pg_cron이 정해진 시각에 포털의 `/api/cron/dispatch`를 호출하고, 포털이 `GITHUB_DISPATCH_TOKEN`(수동 점검 버튼과 같은 토큰)으로 GitHub Actions를 바로 실행합니다. GitHub의 자체 예약은 보험으로 남겨 두었습니다(같은 작업이 겹치면 순서대로 실행되고 결과는 중복되지 않습니다).

- 설정: setup 작업의 `db-update` → `cron-setup` 순서로 한 번씩 실행합니다. 비밀 값은 DB(cron_config, RLS로 외부 공개 API 차단)에 자동 생성되며 화면에 나오지 않습니다.
- 확인: `cron-status` 작업이 등록된 예약, 최근 실행, 포털의 응답 코드를 보여 줍니다.
- 시각(UTC → 한국시간): 위협정보 수집 매시 17분, IP·국가 확인 매시 47분, VirusTotal 3시간마다 40분, 보안뉴스 06:40, 자산 점검 02:30, 정리 03:10.
- 응답 코드가 500이면 Vercel의 `GITHUB_DISPATCH_TOKEN`이 없는 것, 502면 토큰 권한·만료 문제입니다.
